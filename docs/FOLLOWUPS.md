## `css_safe` does not strip `url(` (Designer audit, Phase 11) — deferred to A1.3

`css_safe` in `src-tauri/src/compiler.rs` drops only `{ } ; < > \`, control characters and comment markers. It lets `url(`, `expression(` and `@import` through in the existing 20 style keys. Risk is low (the user writes their own file; Preview's CSP is `default-src 'none'`, `img-src data: asset:`, and the iframe has no scripts), but an exported site has no CSP, so a pasted `url(https://…)` would load remotely.

Decision (Phase 11 A1, 2026-10-26): A1.1 and A1.2 touch no export CSS, so nothing was changed there. **A1.3 is the first step that touches export CSS, so the fix belongs in A1.3**, not B1.1 as `PHASE-11-SPEC.md` §3.2/§10 #18 says: block `url(`, `image-set(`, `expression(`, `@import`, `javascript:` and `behavior:` (case-insensitive, after removing whitespace and comments) in `css_safe`, with hostile fixtures in `compiler_tests.rs`, and the existing goldens unchanged. B1.1 then keeps only the new `css_color()` validator. Do not start A1.3 without Designer approval of the A1.2 targets (spec gate).

**Resolved in Phase 11 A1.3 (2026-10-26):** `css_safe` now rejects a backslash and strips `{ } ; < >`, control characters and repeated comment markers, then returns `""` for any value containing `url(`, `image-set(`, `expression(`, `@import`, `javascript:`, `behavior:`, `-moz-binding`, `vbscript:` or `gradient(`. Covered by `css_safe_*` tests in `src-tauri/src/compiler_a13_tests.rs`. A1.3b (Designer review) added two things: a value with an unterminated quote or paren, or a stray `)`, is rejected (it would have swallowed the rest of the declaration block), and comment-marker removal is now one linear pass (the old repeated `replace` took 21 s for 100k nested pairs and 83 s for 200k; now 200k pairs take about 15–50 ms in a debug build).
