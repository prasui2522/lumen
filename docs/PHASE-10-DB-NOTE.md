# Phase 10 — Database designer (note, not a spec)

**Status:** Direction note only. DEV does not start from it. **Decision: SQLite in the app for local tests, plus a PostgreSQL 17 `.sql` export** (meant for Supabase later). Out of scope: deployment, auth, form submit, and any link between pages and data.

**Why not PGlite:** DEV's spike (`/home/webdev/spikes/db-ram-spike/REPORT.md`, 2026-10-07) measured PGlite 0.5.8 in WebKitGTK 2.52.6 at **+1102 MB RSS** over an empty webview after a 10,000-row workload, with nothing freed by `db.close()`. rusqlite measured **+3.2 MB RSS**. User priorities: stability and low RAM; app size does not matter.

Checked on 2026-10-07 against `src-tauri`. `lib.rs` opens `db_path(app_data_dir)` = `web_builder.db` into `DbState { conn: Mutex<Connection>, assets_dir }`. `open_db` sets `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, then `migrate` (`projects`, `assets`). `delete_project` removes the row only. `Cargo.toml` has `rusqlite 0.32` with `bundled` (lock: rusqlite 0.32.1, libsqlite3-sys 0.30.1 → **SQLite 3.46.0**), so `STRICT` tables (3.37+) and built-in JSON (`json_valid`) are available.

## 1. UI

A third mode in `ModeSwitch`: `ออกแบบ` / `ตัวอย่าง` / `ฐานข้อมูล`. Table cards and relation lines fill the canvas area. The left pane lists `ตาราง`. The right pane edits the selected table or column: `คอลัมน์`, `ชนิด`, `คีย์หลัก`, `ค่าเริ่มต้น`, `ต้องมีค่า`, `ไม่ซ้ำ`, `อ้างอิง`. Actions: `เพิ่มตาราง`, `เพิ่มคอลัมน์`, `ข้อมูลทดสอบ`, `ส่งออก .sql`. The designer is a lazy chunk, like `CommandPalette`. There is no worker or WASM engine; every database call is a Rust command.

## 2. Source of truth

A JSON model in a new table in the existing app DB, added in `migrate`: `db_models(project_id TEXT PRIMARY KEY NOT NULL, model_json TEXT NOT NULL, updated_at TEXT NOT NULL)`. `document_json` does not change, the document version rule (v1–5) does not change, and opening a project rewrites nothing. The model saves with the project (Ctrl/Cmd+S, `บันทึกแล้ว`) and counts toward dirty state. The designer has its own undo history. The SQLite DDL and the `.sql` are both generated from the model, never parsed back.

## 3. Test data file

- One file per project: `app_data_dir/databases/<project-id>.sqlite` (Linux: `~/.local/share/com.webapp.builder/databases/`). It is separate from `web_builder.db`. A bad test schema cannot touch projects, reset and delete are a file operation, and the app DB does not bloat.
- Opened by Rust (rusqlite) on a **second connection** held in its own state (not `DbState.conn`), only while `ฐานข้อมูล` is open. Closed when you leave the mode, close the project, or quit.
- Per connection: `PRAGMA foreign_keys=ON`, `journal_mode=DELETE` (no WAL, so it is one file when closed), `synchronous=FULL`, and `quick_check` on open. A failed check offers `สร้างใหม่`.
- Project rename: nothing changes (the id is stable). `delete_project`: after the row is deleted, remove the file and its `-journal`. If that fails, a startup sweep removes files with no project row.
- Model change → **rebuild**: build `<id>.sqlite.tmp` from the model, then rename it over the old file. A failed build leaves the old file intact. Proposal: drop and recreate, with a confirm dialog (`AlertDialog`, initial focus `ยกเลิก`) saying the test rows will be deleted (Q1).

## 4. Types

SQLite tables are `STRICT`. STRICT allows only `INTEGER`, `REAL`, `TEXT`, `BLOB`, `ANY`, so exact decimals are `TEXT`.

| UI | SQLite (STRICT) | PostgreSQL 17 | Notes |
|---|---|---|---|
| `ข้อความ` | `TEXT` | `text` | |
| `จำนวนเต็ม` | `INTEGER` | `bigint` | 64-bit on both sides |
| `ทศนิยม` (p, s) | `TEXT` + coarse `GLOB` check | `numeric(p,s)` | Rust validates the decimal string and p/s on write. SQLite math or compare on it is text/REAL, so it is not exact |
| `จริง/เท็จ` | `INTEGER CHECK (c IN (0,1))` | `boolean` | default `0`/`1` ↔ `false`/`true` |
| `วันที่` | `TEXT CHECK (date(c) = c)` | `date` | `YYYY-MM-DD`; default `(date('now'))` ↔ `current_date` |
| `วันเวลา` | `TEXT CHECK (julianday(c) IS NOT NULL)` | `timestamptz` | ISO-8601 UTC with `Z`; default `(strftime('%Y-%m-%dT%H:%M:%fZ','now'))` ↔ `now()`. Not `CURRENT_TIMESTAMP`: it has no zone, and PG would read it in the session time zone |
| `รหัส` | `TEXT CHECK (length(c) = 36)` | `uuid DEFAULT gen_random_uuid()` | Rust fills it with `Uuid::new_v4()` (the crate is already used); no SQLite default |
| `JSON` | `TEXT CHECK (json_valid(c))` | `jsonb` | |
| `ลำดับอัตโนมัติ` (key) | `INTEGER PRIMARY KEY` | `bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | no `AUTOINCREMENT` (not needed for tests). `BY DEFAULT` so seed or migrated rows can keep their ids (then `setval`); `ALWAYS` would reject them |

- **Defaults:** only literals (text, number, `true`/`false`) plus the named `now`, `today` and `uuid`. No free expressions.
- **CHECK:** only what the UI builds: `column op literal`, `BETWEEN`, `length(column) op n`, and lists. Emitted on both sides from the model; no hand-typed SQL in v1.
- **Choices (enum):** `CHECK (c IN ('a','b'))` on both sides, not a PG `CREATE TYPE`. The same file runs everywhere, and changing the list is a simple rebuild.
- **NOT NULL, UNIQUE:** as is on both sides. **Composite primary key:** allowed (link tables), with no default on its columns.
- **Collation:** none per column in v1. SQLite `NOCASE` folds ASCII only, while PG needs ICU, nondeterministic collations, or `citext` (an extension). They would behave differently, so case-insensitive email uniqueness is a later item (a `lower()` index works on both).
- **Names:** lowercase `a-z0-9_`, starting with a letter, up to 63 bytes, not a reserved word, not `pg_` or `sqlite_`. Thai is allowed only as a display label, exported as `comment on`.

## 5. Foreign keys

`ON DELETE` defaults to `NO ACTION`. The choices are `NO ACTION`, `CASCADE` (`ลบตาม`), `SET NULL` (`ตั้งเป็นว่าง`, only when the column is nullable) and `RESTRICT` (`ห้ามลบ`). `ON UPDATE` is always `NO ACTION`. SQLite enforces FKs only with `PRAGMA foreign_keys=ON` on that connection (§3). In SQLite the FK sits inline in `CREATE TABLE` (it cannot be added later). In the PG `.sql` all tables are created first, then `ALTER TABLE … ADD CONSTRAINT … FOREIGN KEY`, so order and cycles never break. An index is added for each FK column on both sides.

## 6. `.sql` export

- Its own command and Save dialog (`ส่งออก .sql`). It is not inside the site zip. Default name `<project>-schema.sql`.
- PostgreSQL 17 dialect, schema `public`. Plain statements: create tables, then constraints, then indexes and comments.
- Deterministic: tables by name, columns in model order, PG-style names (`<t>_pkey`, `<t>_<c>_key`, `<t>_<c>_fkey`, `<t>_<c>_check`). The header comment has the app name and "PostgreSQL 17", with no timestamp, so the same model gives the same bytes.
- Identifiers are quoted only when needed. The naming rules make that rare.
- Schema only by default; seed `INSERT`s are optional (Q2). Later, a generated Vite or Next.js project could carry the same file as a Supabase migration. No deployment here.

## 7. Limits

SQLite cannot test RLS, policies, roles, the `auth` schema, extensions, `jsonb` operators, `timestamptz` semantics, or exact `numeric` math. The export dialog, and a badge on affected columns, list what SQLite never ran: `gen_random_uuid()`, identity, `jsonb`, `timestamptz`, `numeric(p,s)`. A later optional PG 17 sidecar could cover these. The spike measured about 61 MB RSS / 21 MB PSS and a 40 ms start, but it carries real packaging and supervision work.
